# Лендинг «от созвона к продуктовым решениям» — дизайн

Дата: 2026-10-28. Репозиторий: `mac-transcribe-site` (Vite + React + TypeScript, лендинг `src/App.tsx` + VitePress-документация `docs/`, деплой GitHub Pages по пушу в `master`). Основание — предложение владельца по переработке сайта (в чате 2026-10-28) и готовый стартовый набор `lite/` из репозитория `product-ai` (master `bd03ed2`).

## Зачем

Сайт сейчас продаёт транскрипцию («Следующий созвон уже можно не конспектировать»). Позиционирование меняется: MacTranscribe — первое звено рабочего процесса продакта «созвон → транскрипт в хранилище → агент (Claude Code или Codex) готовит разбор, сопоставление, договорённости». Посетитель должен за минуту понять, какие материалы получит из своих встреч, посмотреть готовый пример до установки и скачать бесплатный набор, с которым пример повторяется.

Критерий готовности (из предложения): новый посетитель понимает результат, может изучить пример до установки, способен дойти до первой полезной заметки по инструкции.

## Цели

- Первый экран показывает конечный результат, не технологию.
- Три сценария продакта с входом и результатом; главный — сопоставление интервью.
- Один сквозной пример («Смена») с переключением транскрипт → разбор → синтез → требования, где видно качество результата.
- Бесплатный стартовый набор скачивается с сайта без регистрации.
- Два маршрута настройки (с нуля / уже есть база) с отдельными шагами для Claude Code и Codex.
- Честные границы ответственности: MacTranscribe — запись → расшифровка → экспорт; хранилище — накопление контекста; агент — анализ по инструкциям пользователя. Экспорт — кнопкой «В хранилище», автоматики нет и не обещается.
- Возможности приложения привязаны к пользе для продакта; модели и размеры — в раскрываемых подробностях и документации.
- Приватность по этапам, FAQ по реальным препятствиям, финальное первое действие.
- Исправлены устаревшие факты: минимальная macOS 26.0 (сейчас сайт и документация пишут 26.4), размер DMG 40 МБ (сайт пишет 60).

## Не-цели (этап 2 и позже)

- Видео-демо цепочки и пересъёмка скриншотов/`og.jpg` на демо-разговоре — требуют демо-записи в приложении от владельца; на этом этапе скриншот hero остаётся прежним, цепочка показана статической лентой из четырёх карточек с настоящими фрагментами демо.
- Цены и тарифы — пока «бесплатно», без вымышленных условий.
- Реальные кейсы и отзывы — блок появляется, когда появятся.
- Отдельные страницы под каждый сценарий, английская версия, автоматический экспорт.
- Правки самого набора `lite/` сверх README (см. «Набор»).

### 3. Сквозной пример (`#example`)

Заголовок «Одно исследование от начала до конца». Шесть шагов списком (провёл три интервью → MacTranscribe сохранил расшифровки со спикерами и таймкодами → файлы попали в папку исследования → агент сопоставил разговоры → продакт проверил выводы по цитатам → подготовил следующий шаг / зафиксировал, чего не хватает). Затем просмотрщик с четырьмя вкладками, содержимое — дословные фрагменты файлов набора (коммит `bd03ed2` репозитория `product-ai`, папка `lite/`), оформленные как документ:

1. «Исходный разговор» — `Встречи/MT-2026-10-06-1100 Интервью — кофейня «Точка», Марина.md`: имя файла, frontmatter целиком, первые шесть реплик.
2. «Разбор интервью» — `Исследования/… Марина — разбор.md`: первые две проблемы из «## Проблемы» (утверждение, `Источник:`, цитата), первый пункт «## Гипотезы», первый пункт «## Данных недостаточно».
3. «Сопоставление» — `Исследования/Синтез — Почему управляющие ведут график в мессенджере.md`: пункт 1 из «## Противоречия» (Марина ↔ Антон), пункт 1 из «## Гипотезы» («все на Гугл-таблицах»), пункт про «никто не считал» из «## Не проверено».
4. «Следующий документ» — `Требования/Замены смен.md`: по три первых пункта из «Что известно» и «Чего не хватает».

Рядом с просмотрщиком — пять маркеров качества с указанием, где это видно во фрагментах: каждый вывод со ссылкой на источник; цитаты отделены от интерпретаций; противоречия сохранены; неподтверждённые предположения вынесены в гипотезы; для неизвестного — «данных недостаточно». Подпись: «Результаты получены Claude Code по промптам из набора, без ручных правок; имена и компания вымышлены».

Фрагменты лежат в `src/demo-content.mjs` с комментарием об источнике и коммите; копируются дословно, без редактуры.

### 4. Стартовый набор (`#kit`)

Заголовок «Стартовый набор продакта для работы со встречами». Что внутри: структура папок (`Контекст продукта.md`, `Встречи/`, `Исследования/`, `Решения/`, `Требования/`, `_prompts/` с тремя промптами, `AGENTS.md`), демо-транскрипты «Смены», примеры результатов. Абзац про контекст продукта: аудитория, текущая задача, ограничения, вопросы исследования — именно он делает результат полезнее на тех же разговорах. Строка «Работает с любой папкой, Obsidian не обязателен; полезен и с другим способом транскрипции». Кнопка «Скачать набор (zip)» (событие `kit`/`kit`), подпись «без регистрации, около 70 КБ» (архив из `lite/` на `bd03ed2` — 72 КБ).

Распространение: архив `mactranscribe-starter-kit.zip` (внутри папка `Смена-исследование/` = содержимое `lite/`) — ассет релиза с тегом `starter-kit` в публичном `art-ps/mac-transcribe-releases`; ссылка `https://github.com/art-ps/mac-transcribe-releases/releases/download/starter-kit/mactranscribe-starter-kit.zip` живёт в `src/site-content.mjs` как `kitUrl`. Архив собирает скрипт `tools/pack-kit.sh <путь к lite> [путь к check-kit.sh]` в этом репозитории (детерминированно: без `.DS_Store`; перед упаковкой гоняет `check-kit.sh` — по второму аргументу или по умолчанию `<lite>/../tools/check-kit.sh`, без него — FAIL). Скрипт запускается вручную, не входит в `npm test`: в CI сайта приватного `product-ai` нет, загружается командой `gh release upload starter-kit … --clobber` (создание релиза и загрузка — только по явному «да» владельца, до пуша сайта, иначе кнопка отдаёт 404). Обновление набора = повторная упаковка и `--clobber`. Мой выбор: `product-ai` приватный, а публичный репозиторий релизов уже есть; альтернатива — открыть `product-ai` — решение владельца.

`product-ai/lite/README.md` уходит в архив как есть, поэтому в нём не должно быть ничего, что видно только из репозитория (коммит в `product-ai`, без пуша): шаг 1 — «Скачали архив с сайта — распакуйте его в любое место, папка внутри уже называется `Смена-исследование`; из репозитория — `cp -R lite ~/Смена-исследование`», оговорка про работу в копии остаётся только для второго случая; «сравните с перенесённым файлом или с копией в репозитории» → «с перенесённым файлом»; в «Выросли из папки» убрать «инсталлятор в корне этого репозитория» — оставить таблицу соответствия папок и фразу, что правила и промпты переносятся в полное хранилище Obsidian без изменений.

### 5. Настройка двумя маршрутами (`#setup`)

Две колонки.

«Начинаю с нуля»: 1) скачайте и распакуйте набор; 2) MacTranscribe → Настройки → Основное → Хранилище → «Выбрать папку…» → `…/Встречи`; 3) запишите разговор → «Транскрибировать» → «В хранилище»; 4) в терминале `cd` в папку набора, `claude` или `codex`, вставьте текст промпта из `_prompts/` и строку `Файл: …`.

«Уже есть база знаний»: 1) укажите в MacTranscribe папку внутри существующего проекта или хранилища Obsidian (например, `Встречи/` или `50 Raw/MacTranscribe/`); 2) положите рядом `AGENTS.md` и `_prompts/` из набора (Claude Code читает `CLAUDE.md` = `@AGENTS.md`, Codex — `AGENTS.md`); 3) запускайте агента из корня этой папки — остальное как в первом маршруте.

Под колонками: «Экспорт — кнопкой «В хранилище» в меню разговора; автоматического экспорта нет». Ссылка «Подробно, с настройкой доступа к файлам для Claude Code и Codex → документация» на новую страницу `docs/workflow.md`.

Страница `docs/workflow.md` «Встречи → хранилище → агент»: оба маршрута развёрнуто; для Claude Code — запуск в папке, `CLAUDE.md`/`AGENTS.md`, разрешение на правку файлов (подтверждение в чате или `--permission-mode acceptEdits`; в этом режиме дубликат ищется по имени файла); для Codex — `codex` в папке, `AGENTS.md`, песочница `workspace-write`; чем проверено (версии и сценарии); как проверить цитату (таймкод → плеер); где лежат файлы. В сайдбаре — группа «Как это работает». Без ссылок на приватные репозитории и на исходники приложения (существующие тесты документации).

## Мои решения (для проверки владельцем)

1. Набор распространяется zip-ассетом релиза `starter-kit` в публичном `mac-transcribe-releases`, не из приватного `product-ai`.
2. Видео-демо и пересъёмка скриншотов — этап 2; вместо них статическая лента цепочки с настоящими фрагментами.
